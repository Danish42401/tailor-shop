## Common Development Commands

- **Install dependencies**: `npm install`
- **Start development server**: `npm run dev` (runs `next dev` on http://localhost:3000)
- **Build for production**: `npm run build`
- **Start production server**: `npm run start`
- **Run lint checks**: `npm run lint`
- **Run unit tests**: `npm run test`
- **Run unit tests in watch mode**: `npm run test:watch`
- **Run end‑to‑end tests**: `npm run test:e2e` (Playwright)
- **Generate sitemap after build**: `npm run postbuild`

### Running a Single Test
Use Jest's pattern argument, e.g.:
```
npm run test -- -t "cartStore"
```
Replace the pattern with the name of the test you want to execute.

## High‑Level Architecture Overview

- **Framework**: Next.js 14 using the **App Router** (`app/` directory). Pages are defined as server‑components or client‑components under locale‑specific subfolders (`app/[locale]/`), enabling multilingual routing.
- **Internationalisation**: Handled by `next-intl`. Locale is part of the URL (`[locale]`). Content for each language lives in `content/` as JSON files.
- **Styling**: Tailwind CSS with custom CSS variables; dark/light themes managed by `next-themes`.
- **State Management**: Global store implemented with **Zustand**, persisted to `localStorage` for cart, language preference, etc.
- **Content / CMS**: All product data, settings, FAQs, and static copy are stored as JSON under `content/`. The site is a **static‑site‑generated** (SSG) app; Decap CMS edits these JSON files directly in the repo.
- **Search**: Client‑side fuzzy search powered by **Fuse.js** over the product JSON.
- **Forms & Validation**: `react-hook-form` with schema validation via **Zod**.
- **Email / WhatsApp Integration**: Order details are sent using **Resend** (email) and a WhatsApp link generated in `lib/whatsapp.ts`.
- **Utilities (`lib/`)**: Helper modules for blog rendering, Cloudinary image handling, SEO, email templates, product utilities, and site settings.
- **Components**: UI broken into logical groups:
  - `layout/` – site‑wide navigation, header, footer, announcement bar.
  - `product/` – product cards, grids, detail view.
  - `cart/` – drawer and checkout flow.
  - `search/` – modal search component.
  - `ui/` – reusable primitives (dark‑mode toggle, skeletons, social share, etc.).
- **API Routes** (`app/api/`): Serverless functions for daily summary and order processing (`order/route.ts`).
- **Testing**: Unit tests with Jest in `__tests__/unit/`; end‑to‑end tests with Playwright in `__tests__/e2e/`.

## Guidelines for Future Claude Instances
- Prefer using the **App Router** conventions when adding new pages or routes.
- Store any new static content (products, FAQs, settings) as JSON files inside the appropriate sub‑folder of `content/`.
- Update the Zustand store for any additional global state and persist if needed.
- When adding a new API endpoint, create a file under `app/api/<name>/route.ts` following existing patterns.
- Run the full test suite (`npm run test && npm run test:e2e`) after any change that touches logic or API routes.
- Keep the code‑base fully static‑site‑generated; avoid server‑side data fetching that requires a runtime database.

## Security Best Practices

### XSS Prevention
- **Never** use `dangerouslySetInnerHTML` with raw user/CMS content. Always wrap with the `SafeHtml` component (`components/ui/SafeHtml.tsx`), which sanitizes via `lib/sanitize.ts` (DOMPurify).

### Input Validation
- All API routes **must** validate incoming requests using Zod schemas from `lib/validation.ts`.
- Return `400 Bad Request` for invalid payloads with field-level error details.
- Never trust or cast `request.json()` directly without schema validation.

### Rate Limiting
- Apply `checkRateLimit` from `lib/rateLimit.ts` to all public API routes.
- Current limits: `/api/order` → 5 req/min, `/api/daily-summary` → 1 req/hour.

### Environment Variables
- Required env vars: `RESEND_API_KEY`, `OWNER_EMAIL` — the code will throw at startup if missing.
- See `SECURITY.md` for a full list of environment variables and their purpose.
- Never hardcode fallback secrets. Missing env vars should be errors, not silently defaulted.

## Accessibility Guidelines
- All form inputs must have associated `<label>` elements with matching `htmlFor`/`id` pairs.
- Use `aria-describedby` to link hint text to inputs.
- Use `role="alert"` on validation error messages so screen readers announce them.
- Modals and drawers must: focus a meaningful element on open, trap focus inside, and return focus to the trigger element on close.
- Decorative elements (icons, asterisks) should have `aria-hidden`.
